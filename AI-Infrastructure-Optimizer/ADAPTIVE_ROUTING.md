# 보정 기반 작은 모델 우선 라우팅

기존 코드와 실험 CSV를 유지하고 다음 모듈을 추가했습니다.

- `src/adaptive_router.py`: 입력 특징, 신뢰도 판단, Ollama 생성, fallback.
- `src/adaptive_experiment.py`: 보정·평가 분리, 비교 측정, CSV와 프로필 저장.
- `tests/test_adaptive_router.py`: 정답 사전 사용 방지, 오류 fallback, 범위 보존, 지표 검증.

## 기존 거절의 원인

기존 라우터는 난이도 전체의 관측 정확도를 사용합니다. 80% 기준에서 0.5B는 모든 난이도,
1.5B는 중간·어려운 난이도가 부적합합니다. 일반 문장은 산술 난이도를 확신할 수 없으므로
가장 낮은 난이도별 정확도를 적용해 거절합니다. 추가로 기존 프롬프트의 예시 숫자 `123`을
0.5B가 그대로 답하는 현상이 있었습니다. 이 문제를 라우터만으로 해결할 수는 없습니다.

## 개선 정책

새 프롬프트는 숫자 예시 없이 `FINAL_ANSWER:` 형식만 지정합니다. 온도는 기존과 같은 0입니다.
모델은 기존 `qwen2.5:0.5b`, `qwen2.5:1.5b`만 사용합니다.

입력을 작은 피연산자의 덧셈(두 수 모두 1~10), 나머지 기존 범위 덧셈,
기존 중간 곱셈, 기존 어려운 복합식으로 나눕니다. 특징 추출은 문법·피연산자 범위만 읽으며
정답을 계산하거나 기대 정답을 읽지 않습니다. 인식 불가능한 요청은 임의로 쉬운 문제로 취급하지 않습니다.

각 구간·모델의 별도 보정 문제는 20개입니다. 오류와 추출 실패도 오답으로 포함합니다.
95% Wilson 하한이 최소 정확도(기본 0.8) 이상이어야 새 프롬프트로 호출할 수 있습니다.
20/20 정답일 때 하한은 약 0.839입니다. 이 기준도 향후 요청의 정답을 보장하지 않으며,
여러 구간에 대한 동시 신뢰구간이나 시간에 따른 분포 변화까지 보정하지 않습니다.

신뢰할 수 있는 0.5B → 신뢰할 수 있는 1.5B 순으로 시도합니다.
0.5B가 보정 기준에 미달하면 호출하지 않고 1.5B 자격을 확인합니다.
실제 작은 모델 호출의 API 오류·형식 오류가 발생하면 다음 적합 후보를 호출합니다.
기존 라우터가 수용하던 요청에는 기존 모델·기존 프롬프트를 마지막 경로로 보존합니다.
이 호환 경로의 정확도 기준은 기존의 관측 정확도이며 새 Wilson 기준을 통과했다는 뜻이 아닙니다.

기준을 통과한 모델이 없거나 모든 적합 시도가 실패하면 거절 사유와 시도 내역을 기록합니다.
올바른 형식의 오답을 요청 시점에 검출하는 정답 판별기는 없습니다. 그런 응답을 정답을 보고
1.5B로 전환하지 않습니다. 실행 결과에 기대 정답을 전달하는 인터페이스도 없습니다.

## 실행

```bash
.venv/bin/python -B -u src/adaptive_experiment.py --experiment
.venv/bin/python -B src/adaptive_experiment.py --profile data/adaptive_<실행ID>_profile.json --question '2 + 3'
.venv/bin/python -B -m unittest discover -s tests -v
```

실험은 서버·설치 모델을 읽기로 확인하고 모델을 설치하지 않습니다.
새 파일은 고유 실행 ID와 배타 생성 모드로 저장하며 기존 소스·데이터 해시를 검사합니다.
프로필은 보정에 사용한 프롬프트 버전과 함께 저장됩니다.

## 평가 설계와 해석

실행 전 고정 시드로 보정 80개·평가 40개(구간별 20개·10개)를 만듭니다.
기존 CSV의 문제, 보정과 평가 사이 중복, 덧셈·곱셈의 피연산자 교환 중복을 제외합니다.
문제와 기대 정답은 분리 파일에 미리 고정합니다. 프로필을 보정 데이터만으로 저장한 뒤,
평가 정답은 각 방식의 답변 생성 후 채점 단계에서만 읽습니다. 평가를 보고 임계값을 조정하지 않습니다.

동일한 평가 문제에 다음 네 방식을 사용하며 호출 순서를 순환합니다.

1. `fixed`: 기존 프롬프트, 항상 1.5B.
2. `legacy_auto`: 기존 라우팅 기준·프롬프트.
3. `improved`: 보정 기반 작은 모델 우선 및 fallback.
4. `fixed_prompt_control`: 항상 1.5B, 새 프롬프트. 프롬프트 변경 효과를 분리하는 대조군.

기존 라우터의 기준 CSV를 새 평가 데이터로 갱신하지 않습니다. 워밍업은 측정에서 제외합니다.
이는 구간당 10문제의 1회 실험이며 통계적으로 확정된 지연 시간 개선이 아닙니다.
연속 호출의 캐시, 발열, 백그라운드 부하 영향은 순서 순환만으로 완전히 제거되지 않습니다.

`*_evaluation.csv`에는 각 시도의 모델·프롬프트·오류·생성 시간·출력 토큰·Ollama 생성 소요 시간이
포함됩니다. fallback 앞선 시도의 작업도 합계에 포함합니다.
`*_summary.csv`의 전체 정확도는 거절을 포함한 모든 요청을 분모로 하며,
답변 정확도는 최종 정수를 추출한 요청만의 정확도입니다. 형식 오류만 나온 요청은 미답변입니다.
최종 모델 비율은 전체 요청 기준, 호출 비율은 실패를 포함한 실제 모델 호출 기준입니다.

`*_paired.csv`는 두 방식 모두 답변한 **같은 질문들만** 비교합니다. 각 방식의
공통 답변 정확도·시간과 잃은 답변·새로 답한 건수를 함께 기록합니다.
거절로 인한 전체 평균 감소는 속도 개선의 증거로 사용하지 않습니다.
이 교집합 비교가 모든 고정 1.5B 요청의 답변 범위를 유지했다는 뜻도 아닙니다.

보정 시간과 평가 전체 경과 시간은 `*_timing.json`에 별도로 기록합니다.
Ollama 생성 소요 시간과 출력 토큰은 측정한 작업 지표일 뿐, FLOPs·전력·금전 비용이 아닙니다.
비용은 계속 미측정으로 남기며 비용 절감률을 계산하지 않습니다.
