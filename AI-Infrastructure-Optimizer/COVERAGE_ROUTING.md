# 검증 기반 답변 범위 개선

```bash
.venv/bin/python -B src/coverage_runner.py --question '21 * 34'
.venv/bin/python -B -u src/coverage_experiment.py
.venv/bin/python -B -m unittest discover -s tests -v
```

기존 코드와 데이터는 유지하고 다음 모듈을 추가합니다.

- `coverage_policy.py`: 입력 특징과 메모리에 고정한 기존 보정 프로필로 첫 모델을 선택합니다.
- `coverage_runner.py`: 모델 호출, 제한된 fallback, 시도별 시간과 원인을 기록합니다.
- `request_verifier.py`: 명시적인 산술 도구로 입력 식과 모델 출력의 일치를 확인합니다.
- `coverage_experiment.py`: 기존 200문제 재평가와 독립 신규 100문제의 세 방식 비교를 수행합니다.

작은 모델의 20표본·95% Wilson 하한 80% 기준은 유지합니다. 작은 모델이 부적합하면 바로 1.5B를 호출합니다.
이 큰 모델의 사전 품질이 높다고 가정하지 않고, 독립적인 산술 검증에 성공한 응답만 반환합니다.
모델 호출 없이 계산값을 답변으로 반환하는 기능은 구현하지 않았습니다.

실행 검증은 **요청 자체에서 올바른 산술값을 계산하는 도구 기능**입니다. 평가 CSV의 정답과는 분리되지만,
순수 LLM 기반 정책과는 다른 능력을 추가합니다. 이 차이를 성능 보고서에도 명시합니다.
일반 서술형 요청은 검증할 수 없어 거절합니다. 평가 정답을 실행 함수에 전달하는 인터페이스는 없습니다.

0.5B는 최대 한 번, 1.5B는 최초 호출과 재시도로 최대 두 번 호출합니다.
정수 추출 실패·계산 불일치·API 오류가 다음 시도의 조건입니다.
재시도 프롬프트에는 정답, 올바른 중간값, 평가 라벨을 제공하지 않습니다.
유효한 응답을 얻으면 이후 후보를 호출하지 않습니다.

지연에는 선택·검증·실패·거절·재호출이 모두 포함됩니다. `fallback_seconds`는 첫 호출 뒤 추가 호출의
총시간이고 `model_seconds`는 모델별 모든 시도 시간입니다. 신뢰도 부족으로 작은 모델을 건너뛰고
큰 모델을 첫 호출하는 것은 `large_handoff`에 기록하고, 두 번 이상 모델을 호출한 요청의 fallback 비율과 구분합니다.
기존 런타임이 별도로 측정하지 않았던 라우팅 시간은 미측정으로 둡니다.

기존 200문제는 직접 비교를 위해 재사용하며 새 홀드아웃으로 주장하지 않습니다.
신규 100문제는 덧셈 20개, 곱셈 40개, 복합식 40개로 구성합니다. 기존 CSV·JSON의 모든 문제 및
교환 중복을 제외합니다. 남은 덧셈 문제 수가 제한되어 기존 세트와 난이도 분포가 다릅니다.
같은 난이도의 결과도 함께 비교해야 합니다. 평가 중 기준·프롬프트·재시도 횟수를 조정하지 않습니다.

서버와 두 모델을 확인하며 설치하지 않습니다. 모든 결과는 고유 ID의 새 `coverage_*` 파일로
배타 생성하고 기존 파일 해시와 실행 전 고정한 문제 명세 해시를 검사합니다.
금전 비용은 측정하지 않으며 절감률을 추정하지 않습니다.

보고서의 다음 단계는 제안이며 추가 승인 전에는 구현·실행하지 않습니다.
