# 혼합 작업 평가

```bash
.venv/bin/python -B -u src/mixed_experiment.py
.venv/bin/python -B -m unittest discover -s tests -v
```

기존 프로그램은 정수 산술 전용이라 비산술 요청을 거절합니다.
기존 파일을 바꾸지 않고 `mixed_runtime.py`에 **공통 혼합 어댑터**를 추가했습니다.
주 비교는 이 어댑터를 적용한 네 시스템이며 원래 코드 그대로의 혼합 성능이라고 표현하지 않습니다.

- 명확한 산술식: 각 기존 고정/Adaptive/Coverage/Tool 구현을 호출합니다.
- 나머지 요청: 네 시스템 모두 같은 1.5B·객관식 프롬프트·온도0·출력64토큰 상한을 사용합니다.
- 비산술 0.5B의 보정 근거가 없으므로 임의 품질 수치나 선택 기준을 추가하지 않습니다.
- 실제 기존 프로그램의 비산술 거절은 주 비교와 분리한 `legacy_compatibility.csv`로 점검합니다.

`mixed_dataset.py`는 이전에 사용하지 않은 산술·일반 지식·논리·코딩·문장 이해 각20개를 구성합니다.
기존 CSV/JSON의 question 필드와 정규화·교환 중복을 제외하고, 세트와 프로필·소스 해시를 실행 전에 고정합니다.
산술은 기존 난이도 범위를 벗어나지 않습니다. 비산술은 객관식이며 Python 코드의 출력 예측을
포함하지만 생성 코드를 실행하거나 테스트하는 평가가 아닙니다. 일부 논리·지문 문항은 같은 틀의 변형입니다.
수작업 지식 정답과 지문/코드 정답은 모델이 생성한 평가 라벨이 아닙니다.

라우터는 질문 텍스트와 고정 프로필만 받고 유형 라벨·기대 정답·평가 객체를 받지 않습니다.
수식 문법·코드 블록·자연어 지시어로 유형을 추정하고 실제 유형은 사후 오류 집계에만 사용합니다.
숫자나 수식 문자열을 포함한 지문도 전체 입력이 수식이 아니면 계산 도구에 넣지 않습니다.
모든 선택지는 질문의 일부이지만 어느 선택지가 정답인지는 라우터에 전달하지 않습니다.

선택·오류·거절·fallback·검증 시간을 요청 지연에 포함합니다.
모델 워밍업과 ps 자원 수집·채점은 요청 지연에서 제외합니다.
모니터·채점·진행 출력이 포함된 전체 루프 경과 시간도 별도 기록합니다.

CPU와 RSS는 기존 ps 수집기를 재사용합니다. Ollama 및 자식 프로세스의 경계 카운터 차와
샘플 메모리이며 전용 모델 메모리·실제 피크·GPU·도구 Python CPU를 측정하지 않습니다.
접근 실패나 PID 변화 시 미측정으로 남깁니다. 금전 비용·전력·FLOPs는 미측정입니다.

새 `mixed_*` CSV/JSON/Markdown을 배타 생성합니다. 오적용이 없더라도 빈 CSV에 헤더를 저장합니다.
정답 추출은 정수 또는 A~D의 명시적 FINAL_ANSWER 줄을 엄격하게 사용하고 별도 문자열 파서로 교차 검사합니다.
결과가 불리해도 임계값·문제 구성·프롬프트를 평가 도중 바꾸지 않습니다.
비산술에서 네 방식이 같은 경로를 쓰므로, 도구의 효과가 산술에만 나타나면 그 한계를 명시합니다.
