# 해결 방법 자동 선택 300문제 실험

```bash
.venv/bin/python -B -u src/solver300_experiment.py
.venv/bin/python -B -m unittest discover -s tests -v
```

기존 소스·실험을 바꾸지 않고 `solver300_dataset.py`, `solver300_protocol.py`,
`solver300_runtime.py`, `solver300_experiment.py`를 추가했습니다.

정책은 실행 전에 고정합니다.

- Fixed: 항상 1.5B.
- Rule: 명확한 정수 수식은 기존 안전 계산기. 짧은 지식·지문은0.5B. 그 외1.5B.
- Confidence: 유형별 보정에서0.5B의95% Wilson 하한이0.8 이상이고20표본 이상·쉬운 요청이면0.5B. 그 외1.5B.
- Hybrid: 산술 계산기와 Confidence 선택 결합.

난이도는 요청의 연산·문자 수·코드 구조를 이용한 휴리스틱입니다. 별도 정답 난이도 라벨을 읽지 않습니다.
작은 모델의 형식/API 실패만 큰 모델로 전환하고, 큰 모델 실패는 그대로 기록합니다.
내용이 틀렸는지 기대 정답을 보고 fallback하지 않습니다. 큰 모델도 항상 정확하다는 보장은 없습니다.

보정은 과거 혼합100개 중 모호한 소유권4개를 제거한96개와 새 명시적 지문4개입니다.
두 모델을 실제 호출해 보정하며 그 비용을 평가 요청 비용과 분리합니다.
평가는 새로운300개(산술·지식·논리·코딩·문장 이해 각60개)입니다.
정규화·교환 중복뿐 아니라 선택지 순서를 제거한 질문 줄기도 중복 검사합니다.
보정 프로필·문제·소스·출력 계약·재시도 예산을 평가 전에 고정합니다.

출력 계약은 응답 전체의 단일 A~D/정수 또는 유일한 FINAL_ANSWER 줄을 해석합니다.
이 규칙은 평가 전에 정의했고, 원래 엄격한 과거 점수를 덮어쓰지 않습니다.
표준 bare-answer 형식 준수 여부와 해석 불가능 형식 오류·내용 오답을 따로 기록합니다.

런타임은 질문·전략·고정 보정 통계만 받습니다. 평가 정답·유형·참조 코드는 전달하지 않습니다.
호출 본문·클라이언트 요청ID·본문 해시·입출력 토큰·모델/도구·선택 사유·fallback을 저장합니다.
CPU는 Ollama 프로세스군과 라우터 Python을 따로 계측하며 RSS는 경계 샘플입니다.
GPU·전력·FLOPs·금전 비용은 미측정입니다. 로컬 Ollama 외 API나 추가 모델 설치는 사용하지 않습니다.

Hybrid가 Rule보다 정확도가 높아도 시간이 늘면 trade-off로 보고합니다.
품질·답변율을 낮추지 않고 지연·호출·출력 토큰도 늘리지 않을 때만 관측상 우위로 표시합니다.
유형별 문항쌍 bootstrap 신뢰구간은 단일 실행 내부의 표본 불확실성만 반영합니다.
동시 부하·장시간·캐시 독립 반복 검증은 아닙니다.

새 `solver300_<ID>_*` CSV/JSON/Markdown은 배타 생성하며 기존 파일 해시를 대조합니다.
코딩은 자유 코드 생성이 아닌 합성 코드 출력 예측이고, 논리·지문은 템플릿 기반입니다.
문제당 한 번의 실제 실행 결과를 전체 서비스의 일반 성능으로 일반화하지 않습니다.
