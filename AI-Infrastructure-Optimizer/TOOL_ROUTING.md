# Tool-Assisted Routing

```bash
.venv/bin/python -B src/tool_router.py --question '(140 * 93) - 28'
.venv/bin/python -B -u src/tool_experiment.py
.venv/bin/python -B -m unittest discover -s tests -v
```

기존 고정 1.5B·Adaptive·Coverage 구현을 수정하지 않고 새 파일로 추가했습니다.

- `safe_calculator.py`: 전체 입력을 파싱해 명시적인 정수 연산만 계산합니다.
- `tool_router.py`: 도구 결과를 직접 반환하고, 미지원·오류 시 기존 Adaptive로 전달합니다.
- `tool_experiment.py`: Coverage 실험의 같은 200·100문제를 네 방식으로 실제 재측정합니다.

지원하는 문법은 ASCII 정수·괄호·이항 `+`, `-`, `*`·단항 부호입니다.
숫자 하나, 설명 문장, 단위, 소수, 나눗셈, 거듭제곱, 함수 호출, 속성 접근은 도구에 적용하지 않습니다.
Python AST를 파싱만 하고 허용 노드를 직접 순회합니다. 소스 코드를 실행하지 않습니다.
입력 256자, AST 노드 64개, 계산 깊이 16, 리터럴 12자리, 중간 결과 128비트 제한을 적용합니다.

명확한 산술 요청의 계산값은 `FINAL_ANSWER: 정수`로 직접 반환합니다.
이 경로는 Ollama 서버 접속이나 모델 생성이 필요하지 않습니다.
CLI는 기존 프로필 파일을 읽지만 도구 계산의 모델 선택·정답 확인에 이를 사용하지 않습니다.
다른 문제는 질문 원문을 기존 Adaptive에 전달하며, 그 라우터가 적합한 모델을 찾지 못하면 거절합니다.
미지원 문제를 계산 도구가 임의로 해석하거나 일반 문장에 포함된 숫자만 추출하지 않습니다.

실험은 서버와 기존 두 모델을 확인하고 설치하지 않습니다.
기존 프로필과 재시도 정책을 고정하고, 네 방식 실행 순서를 문제마다 순환합니다.
기준 CSV의 정답은 모델이나 도구에 전달하지 않고 응답 후 채점에만 사용합니다.
사용하는 100문제는 Coverage 단계에서 새로 만들었던 세트의 재평가이며 이번에 처음 보는 홀드아웃이 아닙니다.

`direct_calculator_calls`와 Coverage의 `verification_arithmetic_calls`를 구분합니다.
도구 적용 판단 횟수(`calculator_checks`)도 별도 기록합니다.
Coverage가 기존에 검증용으로 계산했다는 사실을 도구 미사용으로 숨기지 않습니다.
모델 호출 수에는 재시도를 포함합니다. 거절과 fallback은 지연 시간에 포함합니다.

주 평가가 모두 지원 산술식이므로 별도 14개 경계·안전 사례도 실행합니다.
이 점검의 지연·호출 수는 주 평가 합계에 넣지 않으며 `probes.csv`에 기록합니다.
선행 0이 있는 수식은 파서가 거부하지만 기존 모델 라우터는 인식할 수 있어 실제 모델 fallback을 점검합니다.
오적용과 fallback은 빈 경우에도 헤더가 있는 별도 CSV로 저장합니다.

고유 실행 ID의 `tool_routing_*` 파일은 배타 생성으로 저장합니다.
기존 소스·데이터 해시와 실행 전 고정한 문제 명세 해시를 검사합니다.
성공은 각 세트에서 기존 각 방식 대비 정확도와 답변 비율이 **모두 엄격히 증가**한 경우에만 선언합니다.
이미 100%인 기준선과 같아지는 경우는 이 엄격한 성공 기준의 개선으로 세지 않습니다.

이 실험은 CPU·메모리·전력·금전 비용을 측정하지 않습니다.
실제 시간과 호출 수는 보고하되 금전 절감률을 만들지 않습니다.
비산술 작업과 일반적인 AI 응답 품질에 대한 성능 개선을 뜻하지 않습니다.
