# 신규 200문제 검증 실행

```bash
.venv/bin/python -B -u src/verify_routing200.py
.venv/bin/python -B -m unittest discover -s tests -v
```

기존 Adaptive 보정 프로필을 고정해 세 방식만 비교합니다. 프로필 경로를 변경하려면
`--profile`을 사용합니다. 평가 결과를 이용한 재학습이나 임계값 최적화는 하지 않습니다.
최소 정확도는 80%이고 기존·개선 라우터의 코드는 변경하지 않습니다.

새 문제 200개는 실행 전 고정 시드로 구성하고 고유 ID의 `verification200_*_splits.json`에 저장합니다.
기존 CSV와 JSON에 기록된 문제 및 덧셈·곱셈의 교환 중복을 제외합니다.
대상 범위의 새 문제 수가 부족하면 기존 문제를 재사용하지 않고 중단합니다.
이번 실행 뒤 같은 좁은 범위에서 또 100개의 새 덧셈 문제를 만들 수 있다는 보장은 없습니다.

서버와 두 설치 모델을 확인하고 워밍업한 뒤 실제 Ollama 호출을 순차 실행합니다.
세 방식의 순서는 여섯 순열을 순환해 위치 편향을 줄입니다. 결과 캐시를 별도로 구현하지 않습니다.
600건의 방식별 요청 중 거절 건은 모델을 호출하지 않으므로 실제 API 호출 수는 더 적을 수 있습니다.

`ps`로 실제 Ollama 및 자식 프로세스의 RSS·누적 CPU 시간을 읽습니다.
프로세스 접근 권한이 없으면 해당 자원 항목은 미측정으로 남습니다.
외부 패키지나 모델을 설치하지 않습니다. 요청 전후 계측은 요청 지연에서 제외되며
전체 루프 시간에는 포함됩니다. 메모리는 경계 두 시점의 샘플이며 실제 피크나 GPU 메모리가 아닙니다.

새 파일은 모두 배타 생성 모드로 저장합니다.

- `*_evaluation.csv`: 원문, 정오답, 시도 내역, fallback, 독립 추출 감사, 요청별 자원.
- `*_summary.csv`: 방식별·문제 구간별 정확도·범위·시간·모델 선택·호출 비율·fallback·자원.
- `*_paired.csv`: 두 방식 모두 답변한 동일 질문의 정확도와 시간 비교.
- `*_resources.csv`: ps에서 얻은 PID별 원시 카운터와 측정 오류.
- `*_metadata.json`: 모델 digest·환경·프로필·데이터 해시·전체 평가 시간.
- `*_report.md`: 실제 결과에 기반한 비교·판단·한계.

금전 비용과 전력은 계측하지 않습니다. 비용 추정치나 절감률도 만들지 않습니다.
테스트의 모의 호출은 임시 디렉터리에서만 수행하고 실제 평가 결과에 포함하지 않습니다.
