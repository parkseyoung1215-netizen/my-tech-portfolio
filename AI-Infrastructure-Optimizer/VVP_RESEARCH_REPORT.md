# Verification Value Predictor 연구 보고서

## 결론
VVP의 성공 조건을 충족하지 못했다. 사전에 지정한 25% 예산에서 두 모델 모두 검증하지 않는 방식보다 정답을 늘리지 못했다. 1.5B에서는 모든 예산에서 검증을 0회 선택했고, 0.5B에서는 검증을 수행했지만 순정답 개선이 없었다. 호출 감소를 새로운 알고리즘의 우월성으로 해석하지 않는다.

**채점 한계의 추가 감사:** 아래 주 분석과 기존 점수는 그대로 보존했다. 미추출 원문 25개를 별도 검토한 [내용 감사 보고서](data/vvp_2a90be1867974c2cbc6862856d207d44_content_audit_report.md)에서는 0.5B 최초 정확도가 50.33%, VVP25 최종은 49.67%였다. 명확한 내용을 인정하면 복구 2건·훼손 4건으로 오히려 순정답 2개를 잃었다. 사후 보조 지표이며 이를 이용해 모델을 재학습하거나 의사결정을 바꾸지 않았다.

0.5B의 VVP25 실제 판단·검증 CPU는 예측 허용량의 약 3.09–3.49배였다. 동일 25% 예산의 Selective보다 CPU도 평균 6.307초 더 사용했다. 호출 상한 준수를 실제 연산 예산 준수로 해석하면 안 된다.

실험 식별자: `vvp_2a90be1867974c2cbc6862856d207d44`. 실제 로컬 Ollama 실행이며 유료 API를 사용하지 않았다. 평가 문제 300개, 모델 2개, 6방식 × 6예산 × 5반복 = 360조건이다. 최종 검증 호출 17,444회, 최초 생성 480회, 학습·보정 수집 1,080회, 결과 행 108,000개를 기록했다. 워밍업 호출은 별도 파일에 있다.

## 1. 설계 및 정보 경계
방법과 주 판정 예산 25%는 평가 검증 전에 고정했다. 나머지 0/10/50/75/100%는 보조 분석이며 좋은 예산만 골라 성공을 선언하지 않는다. 검증 호출 상한과 공통 CPU 비용 예측에 기반한 예산을 동시에 적용한다. CPU 예산은 예측치이므로 실제 CPU의 강제 상한은 아니다. Full의 100%만 전수 검증이며, 낮은 예산에서는 무작위 도착 순서의 부분집합이다. Selective/RCAV/Improved의 기존 게이트는 유지하고 공통 예산 제한만 덧붙였다.

기존 평가 문제를 학습에 전용하지 않았다. 전용 학습 문제 200개/모델, 새 보정 문제 100개, 새 최종 평가 300개를 분리했다. 평가 문제는 산술·일반 지식·논리·코딩·문장 이해 각 60개이며 사전 고정 A/B 집단 각 150개로 나눴다. A/B는 동일 생성 규칙의 부분집합으로 독립 외부 데이터셋이 아니다. 문제의 정답 및 실제 검증 결과는 예측/선택 인터페이스에 전달되지 않는다. 정확도 계산과 Full100 대조는 실행 뒤에만 수행한다.

최초 답변은 모델별 한 번 생성해 모든 조건에서 그대로 사용했다. 산술 60개는 기존 안전한 계산 도구 경로를 공통으로 유지하므로 최초 모델 호출은 240회/모델이다. VVP에만 도구 이점을 주지 않았다. 동일 모델·검증 프롬프트·temperature=0·seed=42·최대 출력 64토큰을 사용했다. 반복별 조건 및 도착 순서는 무작위화했고 모델 언로드와 중립 워밍업을 기록했다. 모델 순서는 1.5B 다음 0.5B로 고정되어 두 모델의 속도 차이는 순서와 완전히 분리되지 않는다. OS/하드웨어 캐시 전체를 제거했다고 주장하지 않는다.

## 2. VVP 알고리즘
다항 로지스틱 회귀로 P(오답→정답), P(정답→오답), 나머지 상태를 추정한다. 최초 관측 가능한 유형·형식·길이·숫자 수·AST 크기·추출/도구 여부만 사용한다. 학습 정답은 전이 라벨 생성에만 사용한다. 기대 가치 EV=P(오답→정답)−P(정답→오답)를 예상 CPU 시간으로 나눠 양의 가치 항목을 우선 배정한다. 이는 탐욕적 예산 배정이며 최적 배낭 해법이 아니다. 안전한 도구의 증명된 결과는 개선 확률을 0으로 제한한다.

검증 CPU 비용은 실제 Ollama 프로세스와 Python CPU 계측에 맞춘 로그 회귀다. 정규화 강도·온도는 보정 집합의 log loss로 선택하고 CPU 규모는 보정 집합의 실제/예측 비율 중앙값으로 맞췄다. 평가에서는 재학습·재보정·임계값 변경을 하지 않았다. 온라인 예측을 위한 추가 AI 호출은 없으며 실제 계획 계산 CPU와 벽시계 시간을 모두 포함했다. 비교군은 공통 예산용 비용 추정만 계산하며 VVP의 분류 비용을 대신 부담하지 않는다.

## 9. 새로움과 기존 기법
기대 효용에 따라 계산 행동을 고르는 관점은 [Selecting Computations: Theory and Applications (2012)](https://proceedings.mlr.press/r10/hay12a.html)의 메타추론과 연결된다. 예측 후 전문가에게 위임할지 학습하는 문제는 [Learning to Defer (2020)](https://proceedings.mlr.press/v119/mozannar20b.html) 등 기존 연구다. 자기 검증이 정답을 훼손할 수 있다는 우려는 [Large Language Models Cannot Self-Correct Reasoning Yet](https://arxiv.org/abs/2310.01798)와 관련되지만 그 연구가 모든 검증의 무용성을 증명하는 것은 아니다.

이 저장소에서 추가한 것은 오답 복구와 정답 훼손을 분리한 간단한 전이 예측기, 실제 CPU 예측을 결합한 예산 선택 및 공유 최초 답변을 이용한 통제 비교다. 로지스틱 회귀·확률 보정·기대 가치·탐욕적 배정 자체를 새로운 기술이라고 주장하지 않는다. 새로운 세계 최초 알고리즘이나 기업 규모 효율을 입증하지 못했다.


## 10. 최종 질문의 답
1. **검증이 유용한 답변을 예측했는가?** 확률의 분별력은 위 지표로 확인할 수 있으나 주 조건의 순정답 개선으로 이어지지 않았다. 실용적인 선택 능력은 입증하지 못했다.
2. **Selective보다 우수한가?** 아니다. 일부 CPU 절감 관측과 전체 성공 조건은 별개이며 사전 지정 성공 조건을 통과하지 못했다.
3. **단순 검증 생략과 다른가?** 설계는 복구·훼손과 비용을 예측한다. 그러나 1.5B에서는 검증 생략과 같은 선택으로 퇴화했고 0.5B 주 조건도 추가 정확도 이점이 없었다.
4. **전체 AI 연산량이 줄었는가?** Selective 대비 측정 단계 CPU·토큰 차이는 표와 CSV에 있다. 최초 생성 비용 합산은 구성요소 계산이며 학습까지 포함한 전체 생애주기 연산 감소나 GPU 연산 감소를 입증하지 못했다.
5. **정확도를 유지했는가?** 기존 채점에서는 No Verification 대비 주 조건 관측 정확도가 동일하지만 Selective 대비 일반화 비열등성은 입증하지 못했다. 별도 내용 감사에서는 0.5B VVP가 최초 정답 2개를 순손실했다.
6. **무엇이 새로운가?** 이 프로젝트에서의 전이별 가치·실측 CPU 결합과 통제 실험 추가다. 기반 학습/의사결정 기법은 기존 방법이다.
7. **AI 기업에 제시할 근거가 있는가?** 재현 가능한 로컬 부정적 실험 자료로는 제시할 수 있다. 제품 성능이나 대형 모델의 비용 우월성을 주장할 증거는 부족하다.
