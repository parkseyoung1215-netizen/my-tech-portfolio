## 기존 거절의 정확한 원인

작은 모델뿐 아니라 큰 모델도 보정 신뢰 기준을 통과하지 못해 정책이 호출 전 거절했습니다.

당시에는 큰 모델이 실제로 답변을 시도했다가 실패한 것이 아닙니다.

## 구현한 변경

생성·검증·선택을 별도 모듈로 나누고 보정 프로필을 메모리에 고정했습니다.
쉬운 요청에는 0.5B를 사용하며 작은 모델이 부적합한 요청은 바로 1.5B에 전달합니다.
작은 모델의 20표본·Wilson 하한 80% 기준은 낮추지 않았습니다.

큰 모델은 신뢰가 확보된 모델이라고 가정하지 않고 **독립 산술 검증을 통과해야 답변을 승인하는 후보**입니다.
검증기는 실행 시 요청 식에서 올바른 정수를 계산합니다. 이는 데이터 라벨 누출은 아니지만
순수 LLM 라우팅과 다른 계산 도구 능력을 추가한 것입니다. 평가 CSV의 정답은 실행 함수에 전달하지 않았습니다.
계산값을 답변으로 직접 반환하지 않았고, 모든 최종 답변은 실제 모델 응답 원문에서 나왔음을 검사했습니다.
프롬프트에도 올바른 정답이나 계산한 중간값을 제공하지 않았습니다.

잘못된 계산·추출 실패·API 오류에 대해 1.5B는 최초 호출과 최대 한 번의 재시도를 허용합니다.
올바른 답변을 얻으면 이후 모델을 호출하지 않습니다. 일반 문장과 미지원 식은 거절합니다.

## 실패와 시간 증가의 원인

1. 큰 모델은 실제로 호출됐지만 충분히 정확한 계산을 만들지 못했습니다.
   기존 세트에서 101건(작은 모델 실패 1건 포함), 새 세트에서 80건이 큰 모델로 전달됐습니다.

3. 추가 호출 시간은 각각 18.490초·21.221초였습니다.
   1.5B 전체 시도 시간은 각각 37.236초·42.252초,
   0.5B 전체 시도 시간은 6.933초·1.856초였습니다.
   산술 검증 시간은 약 0.007초·0.006초로, 시간 증가의 주원인은 검증기가 아닌 모델 재호출입니다.
4. 기존 세트의 마지막 미답변은 계산 불일치 70건과 계산 불일치 뒤 추출 실패 1건,
