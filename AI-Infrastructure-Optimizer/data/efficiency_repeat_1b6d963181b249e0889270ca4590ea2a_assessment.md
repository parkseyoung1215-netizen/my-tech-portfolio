# 반복 실측 최종 평가

실행 ID `efficiency_repeat_1b6d963181b249e0889270ca4590ea2a`. 이전 결과를 보존하고 새로운 실행으로만 평가했다.

## 결론

**보정 프로필을 이미 보유한 운영 구간에서는 Selective Verification의 실측 효율 개선이 확인됐다.** Baseline 대비 세 반복 모두 내용 정확도·답변율을 유지하면서 입력/출력 토큰·처리 벽시계·모델 처리시간·CPU가 감소했다. 하지만 최초 보정을 포함한 이번 3회 분량의 총 시간은 줄지 않았다. GPU 총 연산량·전력·금전 비용 절감을 입증한 것은 아니다.

Selective와 Early Exit의 최종 정규화 답은 **150문제×3회 모두 동일**했다. 이 동일 답변 범위에서 Selective는 평균 처리시간14.37%, 모델 처리시간14.87%, CPU11.69%, 모델 호출12.50% 감소였다. 따라서 단순 거절이나 답변 누락으로 빨라진 결과는 아니다. 원본 출력 형식 준수는96.67%로 Early Exit98.67%보다 낮지만, 안전한 해석 후 답변율은 두 방식 모두100%다.

Baseline은 전수 재검증하는 연구용 대조군이며 최선의 기존 생산 시스템을 뜻하지 않는다. 여기서 Baseline을 이겼다고 모든 서비스에서 최적이라 할 수 없다. 묶음 검증의 내용 정확도68.00%는 Selective66.67%보다 높지만 훨씬 느리고 CPU 사용량도 크다. 최대 정답률과 최소 처리량을 모두 달성한 하나의 방식은 확인되지 않았다.

총 처리시간은 각 방식의 실제 블록 처리 벽시계 합계다. 평균 완료 지연은 최대4개 요청이 블록 시작에 동시에 도착한 조건에서 순차/묶음 대기를 포함한다. 모델 처리시간은 Ollama의 prompt_eval_duration+eval_duration이며, 생성시간만 보고 판단하지 않았다. 서버 total_duration·로딩·Python CPU는 별도 CSV/기본보고서에 있다. CPU는 실제 Ollama 프로세스군 카운터 차이며 모든 방식·반복40/40블록에서 측정됐다.

RSS는 블록 양끝 표본의 최대이며 피크·전용 모델 메모리가 아니다. 1차 약1545MiB에서 후속 반복 약1900MiB로 커지는 공유 프로세스 상태가 관측돼 방식별 작은 차이를 메모리 절감으로 해석하지 않았다. 동일 모델·서버의 warm-cache 상태를 공유했으며 캐시/발열/부하를 완전히 분리하지 않았다.

## 무엇이 줄었는가

- **Selective:** Baseline 대비 호출22.22%, 입력토큰18.56%, 출력토큰33.02%, 실제 처리시간10.70%, 모델 처리시간11.48%, CPU16.91% 감소. 세 반복 모두 같은 방향이었다. 내용 정답87→100/150, 답변율100% 유지, Baseline 정답을 잃은 문항0개였다. 쉬운 지식의 모델 재검증30회 추가 생략이 Early Exit와 동일한 최종 답을 유지했다.
- **Early Exit:** 안전 산술 재검증30회 생략으로 산술18→30/30 정답, 호출11.11%·출력23.47%·CPU5.92% 감소. 그러나 모델 처리시간은평균3.98%, 전체 처리시간4.28% 증가했다. prefill이 평균13.513→15.368초로 커져 생성시간4.704→3.574초 감소를 상쇄했다. 왜 prefill이 달랐는지 캐시/스케줄링 원인을 분리하지 못했으며, 호출 감소만으로 속도 개선이라고 하지 않는다.
- **출력 상한:**64→8토큰 상한에도 출력639토큰·호출270회로 Baseline과 동일했고 상한에 의한 잘림 종료는 없었다. 모델 처리시간10.57%, CPU11.93%, 처리시간11.10% 증가해 절감 근거가 없다. 정답+1문항은 같은 프롬프트라도 관측된 답 차이와 얽혀 상한의 품질 개선으로 확정하지 않는다.
- **묶음 검증:** 호출40.74% 감소에도 출력228.48%, 모델 처리시간93.30%, CPU148.56%, 처리시간86.17% 증가했다. 정답102/150로 높았지만 Baseline 정답18개를 잃고33개를 새로 맞히는 교체도 있었다. 요청별 손실을 총점으로 가리지 않았다. 현재 조건에서 효율 개선 방식으로 판단하지 않는다.

위 백분율은 **새 반복 실측 평균의 상대 차이**이며 금전 비용 절감률이 아니다. FLOPs·전력·GPU 사용량·금전 비용은 미측정이며 임의 추정값은 만들지 않았다.

## 형식과 내용, 이전 점수와의 구분

정답을 입력받지 않는 새 파서는 전체 응답에서 단일 답·정확한 옵션 표기/본문·단일 코드펜스를 안전하게 해석한다. 옵션 본문 충돌, 모호한 답, 중복JSON키, 누락/추가ID는 계속 거부한다. 채점기는 해석된 답을 실행 후에만 정답과 비교한다. 미해결 내용과 해석된 내용 오답, 형식 불준수를 서로 다른 필드로 기록한다.

묶음 검증120개 실제 응답 모두 바깥 JSON 코드펜스를 사용했다. 새 파서는150×3개 답을 정상 해석·채택했지만 원래 코드펜스 없는JSON 계약은0% 준수였다. 이는 최종 답이 모두 비어 있거나 내용 정확도가0%라는 뜻이 아니다. 최종 정규화 답은 전부 반환 가능했고 내용 정확도68%다. 모든 고유 모델 호출의 형식 준수율은 묶음72.50%, Baseline97.78%, Early Exit97.50%, Selective97.62%, 출력상한97.78%로 별도 집계했다.

예를 들어 수도 답 `A) Warsaw`는 내용은 맞지만 원래 단일 문자 형식은 어겼다. 반대로 논리 역명제301의 검증 답 `A)`는 형식 포장을 해석할 수 있어도 정답B와 다르다. 예전에는 이 검증 답을 버리고 원래 정답B를 보존했지만 새 런타임은 오답A를 채택한다. 형식 수정을 좋은 결과만 골라 적용하지 않았으며, 이 악화도 새 정답률에 포함했다.

과거 텍스트 재해석은 당시 **채택된 최종 답만** 읽은 사후 내용 지표다. 새 실행에서는 이전에 버렸던 검증 응답을 실제 채택하므로 서로 같은 지표가 아니다. 기존 CSV·공식 보고서를 덮어쓰지 않았고 legacy_regrade.csv와 새 실행 CSV를 분리했다. 과거 실행보다 새 벽시계가 짧아진 것을 파서 수정 효과라고 주장하지 않으며, 효율 판정은 같은 새 반복 안에서 수행했다.

## 보정 비용을 포함하면

보정100문제180호출, 입력17856/출력415토큰, 실제 벽시계 17.750초, 서버 모델 처리 합계 16.703초를 별도 측정했다. 프로필 SHA-256과 사전 판단계획은 이전 실험과 동일했고, 평가 응답을 보고 생략 기준을 조정하지 않았다.

새 3회 실행 블록 합계는 Baseline 58.383초, Early Exit 60.883초, Selective 52.137초다. 보정1회 비용을 Selective 도입비용으로 포함해 실제 측정 구간을 합산하면 69.887초로, 이번3회 분량에서는 두 비교군보다 길다. 이 합산은 별도 독립 배포 실행의 측정값이 아니며 프로필 재사용/상각을 가정하지 않는다. 보정 포함 평가 호출 합계도 Selective630+180=810회로 Baseline810회와 같다. 최초 도입 전체의 비용 절감을 달성했다고 하지 않는다. 보정 CPU·RSS는 계측하지 않아 합산하지 않았다.

전체 다섯 방식 평가 루프 383.994초에는 계측·사후채점·반복 CSV 저장도 포함된다. 그 전의 워밍업1회는 warmup.json에 실제 응답·토큰·서버 시간을 저장했고 보정과 평가 호출에서 분리했다.

## 남은 한계와 감사 결과

- 새 평가 데이터가 아니라 이전150문제를3회 재생했다. 동일150문제를450개 독립 문제로 간주하지 않았다. 파서 수정은 이전 로그의 형식 오류를 바탕으로 했으므로 새로운 분포 일반화의 증거가 아니다.
- 정답률과 토큰 수는 세 반복에서 같았지만 시간은 달랐다. 세 번·단일seed·단일기기 결과로 통계적 비열등성이나 일반적 서비스 우위를 확정하지 않는다. question_repeats.csv에는 문항별 지연 평균/범위/표본표준편차·답 변동도 기록했다.
- Selective의 검증 전 답은 매 반복105/150(70.00%) 정답, 검증 후100/150(66.67%)였다. Baseline도106→87, 묶음105→102였다. 재검증이 전체 품질을 해치는 문제는 여전히 남았다. 이는 실제 관측 중간 답의 사후 채점이며, 재검증 없는 별도 방식의 실제 처리시간을 측정한 것은 아니다.
- 영어 객관식·산술·수도 지식·합성 논리/지문·코드 출력 예측에 제한된다. 자유 서술 내용은 임의로 의미 판정하지 않고 명확히 해석할 수 없는 답은 미해결로 남긴다.
- 기존 154개 파일의 해시 유지, 보정/평가 중복0, 고정된 프로필·사전계획 유지 확인. 런타임 prompt는 질문과 실제 후보만 포함함을 전수 재구성했다. 평가 정답은 생략 판단에 전달하지 않았다.
- 2250개 요청 결과, 3450개 고유 모델 호출, 공유 검증 호출 중복집계0, API오류0. 정답·형식·반복요약·평균/범위·쌍별 비교를 로그에서 재구성해 일치 확인했다.
- 자동 테스트150개 통과. 모의 응답은 임시 디렉터리 단위 테스트에만 사용했다. 실제 결과는 로컬 Ollama에서 생성됐고 유료API·새 모델 설치는 사용하지 않았다.
