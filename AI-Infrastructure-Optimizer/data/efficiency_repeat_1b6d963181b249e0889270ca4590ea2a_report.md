## 고정 설계와 형식 수정

기존 skipwork150문제(유형별30)를 동일하게3회 반복했다. 이것은 새 holdout 일반화 평가가 아니라 기존 평가의 신뢰성·변동 검증이다. 모델 qwen2.5:1.5b, temperature=0, seed=42, 프롬프트·출력예산64/8/128·최대4개 묶음을 유지했다. 새 라우팅 규칙을 추가하지 않았다. 블록 순서를 반복마다 사전 섞고, 방식 순서를 블록·반복에 걸쳐 순환했다.

Baseline은 기존 Hybrid 해결(도구 또는1.5B) 후 전수 검증하는 연구용 대조군이다. Early Exit는 안전 산술 도구의 재검증 생략, Selective는 별도 보정에서 순이득이 없던 쉬운 유형의 검증 생략이다. 수정된 판정기로 별도100문제 보정을 한 번 수행하고 기존 규칙 그대로 프로필과 모든 사전 결정을 고정했다. 평가 정답은 실행 후 채점에만 사용했다.

내용 추출은 전체 응답의 단일 문자/정수, 단일 FINAL_ANSWER, 정확한 옵션 표기/본문, 단일 코드펜스를 허용한다. 기대 정답을 받지 않으며 애매한 답·옵션 본문 충돌·중복JSON키·누락/추가ID는 거부한다. 묶음의 JSON 코드펜스는 내용으로 해석하지만 원래JSON출력 계약 준수로 인정하지 않는다. 검증이 해석되지 않으면 원래 답을 보존한다.

내용 정확도는 해석된 정답/전체 요청이고 미해결도 분모에 넣는다. 미해결과 해석된 오답은 CSV에 분리했다. 형식 준수율은 정규화 전 실제 채택 응답이 원래 계약(단일 대문자/정수, 묶음은 코드펜스 없는JSON)을 지킨 비율이다. 시스템이 반환할 정규화된 답의 형식100%와 혼동하지 않는다. 모든 고유 모델 호출의 형식 준수율도 별도 기록한다.

## 비용·자원·보정 한계

보정 180호출, 17.750초, 입력17856/출력415토큰은 반복 표에서 분리했다. 평가 전체 루프 383.994초는 모니터링·채점·반복 파일 저장을 포함한다. 워밍업1회는 별도JSON에 기록했다. 처리 벽시계에는 추출·라우팅·검증 실패·원래 답 보존을 포함하며 ps수집/사후채점은 제외한다.

Ollama 프로세스군 CPU 카운터와 Python process_time을 실제 수집했다. RSS는 블록 양끝 실제 표본으로 피크/전용 메모리나 모델별 독립 메모리가 아니다. 같은 로컬 서버·가중치·prefix cache를 공유하는 warm 상태 실험이다. 캐시를 강제로 비우지 않았고 백그라운드 부하·발열·순서 효과를 완전히 분리하지 못했다. 입력토큰은 서버 카운트이며 캐시를 제외한 실제prefill FLOPs를 뜻하지 않는다.

**금전 비용·전력·GPU FLOPs는 미측정이며 추정 절감률도 만들지 않았다.** 호출·토큰·모델 처리시간·CPU·사용자 지연은 각각 다른 지표로 판단한다. 보정 최초 비용의 상각도 가정하지 않는다. 영어 객관식·수도 지식·합성 논리/지문·코드 출력 예측이라는 평가 범위가 한계다.
