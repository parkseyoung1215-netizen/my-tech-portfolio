# 신뢰성 감사 결론

기존 혼합 평가의400개 응답을 재분석했습니다. 모델 재실행이나 라우팅 변경은 없었고,
원래 점수·라벨·CSV·보고서·소스는 모두 보존했습니다. 새 지표는 사후 내용 평가이며 기존 실측을 대체하지 않습니다.

## 기존 평가와 내용 평가

응답에 유일한 FINAL_ANSWER 줄이 있거나 응답 전체가 단일 선택지/정수일 때만 내용 답을 추출합니다.
설명문에서 답을 추측하거나 여러 후보 중 정답을 고르지 않습니다. 추출 함수는 기대 정답을 받지 않습니다.
Coverage가 검증 실패로 반환하지 않은 후보도 답변으로 복원하지 않습니다.

| 방식 | 기존 정확도 | 내용 정확도 | 기존 승인 답변 비율 | 내용 해석 가능률 | 내용이 해석된 답변의 정확도 |
|---|---:|---:|---:|---:|---:|
| 고정 1.5B | 34% | 72% | 55% | 100% | 72.00% |
| Adaptive | 31% | 69% | 41% | 86% | 80.23% |
| Coverage | 38% | 76% | 48% | 93% | 81.72% |
| Tool-Assisted | 45% | 83% | 55% | 100% | 83.00% |

앞 두 정확도는 동일한 전체100문제를 분모로 합니다.
내용 해석 가능률은 과거 서비스가 실제 승인한 답변 비율이 아니라, 저장된 원문을 사후 규칙으로 해석할 수 있는 비율입니다.
실행 경로·호출·지연은 바뀌지 않았으므로 새로운 채점기를 배포한 성능이라고 주장하지 않습니다.

| 일반 지식 | 20% → 100% | 20% → 100% | 20% → 100% | 20% → 100% |
| 논리 | 20% → 55% | 20% → 55% | 20% → 55% | 20% → 55% |

네 방식 모두 비산술80문제 중45개에서 접두어 없이 선택지 한 글자를 반환했습니다.
그45개는 **형식만 오류38개, 형식과 내용 모두 오류7개**입니다.
형식이 맞은35개에도 내용 오답10개가 있어, 비산술 내용 오답은 총17개입니다.
형식 실패를 전부 모델의 지식 부족으로 보거나 접두어만 고치면 모두 맞는다고 보는 해석은 둘 다 틀립니다.

원래 summary의 format_failures는 '호출 후 미답변'을 뜻하는 잘못된 필드 이름으로,
Coverage의 산술 검증 실패7개까지 포함했습니다. 새 문항별 감사에서는 이를 분리했습니다.
원본 필드나 원래 점수는 덮어쓰지 않았습니다.

## 실제 모델·도구 선택과 응답 동일성

| 방식 | 산술20개 실제 호출 | 비산술80개 실제 호출 |
|---|---|---|
| 고정 1.5B | 1.5B 20회 | 1.5B 80회 |
| Adaptive | 0.5B 6회, 나머지14개 정책 거절 | 1.5B 80회 |
| Coverage | 0.5B 6회 + 1.5B 24회 | 1.5B 80회 |
| Tool-Assisted | 직접 계산20회, 모델0회 | 1.5B 80회 |

각 문항별 첫 선택·전체 모델 호출 순서·최종 기록 모델·도구·답변 원문은 per_question.csv에,
각 문항의 토큰·시간·자원은 request_usage.csv에 기록했습니다.
첫 선택과 최종 답변 여부를 분리해, 모델을 호출했지만 형식 때문에 거절된 사례를 미선택으로 오인하지 않도록 했습니다.

비산술은 네 방식 모두 공통 어댑터가 같은1.5B·동일 프롬프트·온도0·출력64토큰 상한으로 전달했습니다.
문항별 실제 응답이 같은 경우는80/80개이고 모델 시도는 각80회·총320회입니다.
현재 코드에는 결과를 복사하거나 별도 캐시로 모델 호출을 건너뛰는 경로가 없습니다.
같은 요청 조건과 온도0이 동일성의 구조적 원인입니다.

다만 실제 HTTP 본문·요청ID·서버 seed·캐시 hit 로그는 남아 있지 않습니다.
identity.csv의 해시는 고정된 코드로 재구성한 본문 해시이지 당시 네트워크 캡처가 아닙니다.
서버 내부 캐시나 모델의 비결정성까지 배제했다고 주장하지 않습니다.
비산술80개는 모두 정상 stop으로 종료됐으며 출력 상한으로 잘린 사례가 아니었습니다.

출력 토큰은 실패·재시도를 포함한 모든 모델 호출에 기록돼 있습니다.
입력은 고정 방식의 산술20회에서만1359토큰이 기록돼 있어, 이를100회 전체 사용량으로 표시하지 않았습니다.
전체 입력·입출력 총 토큰·금전 비용은 미측정입니다.

RSS 경계 최대는 네 방식 모두1920.984MiB였습니다. 메모리 감소는 확인되지 않았습니다.
CPU는 Ollama 및 자식 프로세스군의 실제 경계 카운터 차이고 도구/어댑터 Python CPU·GPU 연산은 제외합니다.
RSS는 상주 모델·공유 페이지를 포함할 수 있어 전략별 전용 메모리나 연속 피크가 아닙니다.
전력·GPU 자원·FLOPs·전체 하드웨어 비용은 미측정입니다.
지연에는 라우팅·거절·검증·fallback이 포함되고 워밍업·모니터 수집·사후 채점은 제외됐습니다.

## 비용·정확도 개선은 어디에서 발생했는가

Tool과 고정 방식의 내용 정확도 차이는11개 정답(72→83), 모델 호출 차이는20회(100→80),
출력 토큰 차이는186개(486→300)입니다. 이 차이는 모두 산술에서 발생했습니다.
비산술은 정답63/80, 호출80회, 출력300토큰으로 네 방식 모두 같습니다.

따라서 지원 산술식에서는 품질을 개선하면서 실제 모델 작업과 지연을 줄였다는 증거가 있습니다.
그러나 혼합 작업 전반의 모델 선택이 개선됐다는 증거는 없습니다.
Tool과 고정 방식의 내용 해석 가능률은 둘 다100%라 답변 범위가 늘어난 것도 아닙니다.
금전 청구·전력·GPU 비용을 측정하지 않아 실제 총 추론 비용 절감액은 입증하지 못했습니다.
호출20%·출력 토큰 약38.3%·요청 처리 시간 약35.5% 감소를 금전 절감률로 바꾸지 않았습니다.
단일 실행의 캐시·호출 순서·백그라운드 부하 영향과 작은 표본의 한계가 남습니다.

## 정답 판정과 데이터 누출

- 원래400행의 예측·정오답·답변 건수를 독립 추출기와 대조해 원래 점수를 재현했습니다. 계산 불일치0건입니다.
- 산술은 별도 AST 계산, 코딩은 기록된 격리 Python 기준 출력20건과 선택지 대응을 점검했습니다.
- 논리는 규칙 추론, 일반 지식은 기초 사실 수작업 검토, 지문은 명시적 내용을 검토했습니다.
  지식 검토는 외부 기관 자료로 독립 검증했다는 뜻이 아닙니다.
- 96개 라벨은 검토 기준과 일치했고 소유권 지문4개는 모호성으로 표시했습니다.
  빌려준 사람이 반드시 원소유자라고 단정할 수 없으므로 정답 라벨 정리가 필요합니다.
- 이4개의 라벨·점수는 변경하지 않았습니다. 내용 정확도도 기존 라벨 기준임을 명시합니다.
- 기존 프로젝트 평가와의 중복0, 실행 전 문제 명세·프로필·소스 해시, 네 방식의 동일100문제를 확인했습니다.
- 런타임 호출부는 질문·전략·기존 프로필·정책만 받고 정답·유형은 사후 채점에만 사용합니다.
  감사 범위에서 라벨 누출 정황은 없었습니다. 사전학습 중복이나 저장하지 않은 서버 상태까지 증명한 것은 아닙니다.
- 감사 중 모든 기존 소스·실험 파일의 해시가 유지됐습니다. 새 감사 파일만 만들었습니다.
- 자동 테스트112개가 통과했고, 감사 전체를 네트워크 금지 상태에서도 검증했습니다.

## 판단과 다음 신뢰성 검증

현재45%는 내용 정확도만을 뜻하지 않고 형식 준수까지 요구한 점수였습니다.
83%는 동일 응답을 보수적인 내용 규칙으로 해석한 사후 보조 지표이며 새로운 모델 성능이나 배포 결과가 아닙니다.
수치를 바꿔 성공으로 포장하지 않고 두 지표를 함께 유지해야 합니다.

새 라우터를 추가하기 전에 출력 계약을 명확히 정하고, 모호한 라벨4개를 해결한 새 독립 세트에서
형식 준수·내용 정확도·답변 범위를 따로 측정하는 것이 우선입니다.
입출력 토큰·요청ID·캐시/모델 로딩·Python/GPU 자원 기록을 보완하고 반복·부하 실험으로 비용과 지연을 검증해야 합니다.
이번에는 이러한 변경이나 모델 재실행을 진행하지 않았습니다.
