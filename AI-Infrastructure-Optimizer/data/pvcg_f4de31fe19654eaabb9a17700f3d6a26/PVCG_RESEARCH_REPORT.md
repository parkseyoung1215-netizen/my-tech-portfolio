# Pre-Verification Compute Gate (PVCG) 연구 보고서

## 결론
**PVCG의 성공 조건을 충족하지 못했다. 새로운 비용 절감 기술을 발견했다고 주장하지 않는다.** 두 모델 모두 검증을 0회 선택해 No Verification으로 퇴화했다. 같은 정확도에 추가 판단 비용이 발생하므로 검증을 모두 생략하는 방식보다 유리하지 않다.

실험 `pvcg_f4de31fe19654eaabb9a17700f3d6a26`. 신규 평가300문제, 2모델 × 4방식 × 5반복 = 40조건, 실제 결과 12,000행이다. 실제 평가 검증 호출 4,500회, 공통 최초 모델 생성 480회, 신규 보정 수집 360회, 검증 루프 벽시계 634.825초(워밍업·언로드·저장 포함)를 기록했다. 모의 응답은 성능 수치에 사용하지 않았다.

## 1. VRG 실패에서 출발한 설계
VRG는 수정안 생성 뒤 거절해 정답 파괴를 줄였지만, 이미 지출한 검증 호출·토큰·CPU를 줄이지 못했다. PVCG는 최초 답변 직후 검증 호출 **전**에만 판단한다. 기존 Selective가 검증하려는 집합을 더 걸러내며 수정안이 나오면 모든 검증 방식에 같은 채택 규칙을 쓴다. 수정안을 본 뒤 PVCG 판단을 뒤집는 경로는 없다.

PVCG의 관측 입력은 문제에서 추정한 유형과 최초 답변의 추출/형식 상태, 계산 도구 여부다. 추가 LLM 호출은 없다. 학습 자료의 유형×상태별 검증 복구/훼손/유지 횟수에 중립 Dirichlet(1,1,2) 사전값을 두고 기대 순이익을 추정한다. 표본10개 미만은 유형 전체로 backoff하며 여전히 부족하면 생략한다. 기대 이익−불확실성 가중 표준오차가 비용 가중치×과거 검증 CPU 중앙값을 넘을 때만 검증한다. 이 점수는 보장된 신뢰 하한이나 실제 CPU 측정값이 아니다.

기존 학습 전용200문제/모델을 사용했고 이전 평가나 이전 VVP 보정 문제를 학습으로 전용하지 않았다. 새로운 보정100문제에서 불확실성 가중치0/.5/1, CPU 가중치0/.05/.2를 비교했다. 보정 정답 수 최대, 동률이면 보정 실측 검증 CPU 합계 최소, 다시 동률이면 보수적 설정을 택했다. 최종 평가의 정답이나 검증 결과로 재조정하지 않았다. No Verification으로 퇴화하면 실패로 보고하도록 사전에 정했다.

## 2. 데이터·환경·공정성
시드 **78112026**. 신규 보정100개와 최종 평가300개를 분리했으며 산술·문서 기반 지식 검색·논리·코딩·문장 이해를 각각20/60개 포함했다. 문서 검색은 제공된 가상 서비스 카탈로그에서 사실을 찾는 합성 작업이며 일반 상식 회상 능력으로 표현하지 않는다. 카탈로그의 작업 문맥은 정상 입력이고 실제 정답 선택지 라벨은 모델 입력에 붙이지 않았다.

과거 CSV/JSON과 정규화한 문제 줄기/보기 순서 교체/산술 중복을 확인했다. 새로운 문자열이 의미적 독립을 보장하지는 않으며 보정·평가 생성 템플릿도 일부 공유된다. 각 유형의 반씩을 고정 A/B 집단 각150개로 나눴다. 이는 외부 독립 평가셋이 아니다.

기존 `qwen2.5:1.5b`, `qwen2.5:0.5b`를 그대로 사용했다. temperature0, seed42, 최대 출력64토큰, 기존 생성/검증 프롬프트와 VRG의 고정 내용 추출 규칙을 공유했다. 형식 준수율은 내용 정답률과 별도 측정한다. 산술60개는 모든 방식에서 기존 안전 계산 도구로 처리해 최초 모델 호출은240회/모델이다. 도구의 이점을 PVCG 성과로 취급하지 않고 AI 최초 생성240문제의 하위 결과도 보고한다.

최초 답변을 모델별 한 번 생성해 모든 방식·반복에서 공유했다. 모든 평가용 검증 호출 전에 선택 계획까지 동결했고 실행 시 다시 판단해 동일성을 검사하며 판단 CPU/시간을 계측했다. 검증을 선택한 Full/Selective/PVCG는 유효한 수정안을 채택하고 미추출이면 원답을 유지한다. 이는 공통 추출 실패 처리이며 VRG식 수정안 선택기가 아니다. 네 방식 모두 공통 입력 경계 검사/유형 해석을 수행하므로 No Verification도 Python 비용이 있다. 가장 단순한 원답 반환 구현은 이보다 저렴할 수 있으며 이를 PVCG의 이점으로 계산하지 않는다.

방식의 무작위 기본 순서를 회전시켜 첫4반복 위치를 균형화했다. 5회차는 한 위치를 반복하므로 완전한 위치 균형이 아니다. 모델 순서는 교대하고 모델 언로드·중립 워밍업·문제 도착 순서를 기록했다. OS/하드웨어 캐시와 노트북의 모든 배경 활동을 완전히 통제하지는 못했다. 실제 검증 호출은 방식별로 별도 실행했다.

## 9. 최종 판단과 다음 연구
이번 설정은 두 모델 모두 No Verification과 동일한 선택으로 퇴화했다. Selective/Full 대비 호출·CPU가 줄어도 No Verification보다 유리하지 않고, 더 나은 정확도도 얻지 못했다. 따라서 의미 있는 새 연산 절감 방법을 발견하지 못했다.

PVCG는 기존 verification gating 및 경험적 검증 이익 추정의 적용이며 VVP/Selective와 근본적으로 독립된 새 기술이라는 근거는 없다. 이 실험에서 실측한 것은 CPU·토큰·호출·벽시계다. 이를 GPU FLOPs나 전력·금전 절감으로 확장하지 않는다. 학습 비용까지 포함한 전체 생애주기 절감 역시 확인하지 못했다.

다음 우선 과제는 더 많은 게이트를 추가하는 것보다 **외부 근거가 있는 검증기가 실제 복구 이익을 내는지** 먼저 확인하는 것이다. 틀린 유효 답변을 복구하고 정답을 훼손하지 않는 검증 신호가 있어야 호출 전 예측도 학습할 수 있다. 복구/훼손 사례를 별도 학습 자료로 확보하고 외부 업무 분포에서 사전 등록해 검증해야 한다. 후속 개발은 이번에 진행하지 않았다.
