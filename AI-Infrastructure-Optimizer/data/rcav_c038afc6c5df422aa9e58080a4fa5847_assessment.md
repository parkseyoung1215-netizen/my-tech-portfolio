# RCAV 최종 연구 평가

실행 ID `rcav_c038afc6c5df422aa9e58080a4fa5847`. 주 RCAV의 사전 가중치는 λ=0.05다. λ=0/0.15는 공개 감도분석이며 사후에 주 방법으로 바꾸지 않았다.

## 판정

**일관된 품질 유지형 절감 알고리즘으로 성공했다고 판단하지 않는다.** 1.5B에서는 Selective보다 전체 정확도가2%p 높고 측정 시간·CPU가 감소했지만,0.5B에서는 정확도가1.33%p 낮아졌다. 1.5B의 주 RCAV는 실제로 검증을 전부 생략한 퇴화 사례이며, 두 모델 모두 비용 회귀가 상수로 축소됐다. 이 실험만으로 요청별 위험·계산비용을 정교하게 적응시키는 능력을 입증하지 못했다.

## 알고리즘과 실험 조건

RCAV는 검증 이전에 이미 존재하는 질문·실제1차 답·내용 추출 상태·추정 유형/난이도만 사용한다. 별도 보정 데이터로 오류위험p, 오답수정확률r, 정답악화확률h를 추정하고 Δ=p×r−(1−p)×h를 계산한다. 검증입력길이로 예측한 모델 처리시간C와 보정 중앙시간Cref에 대해 Δ>λC/Cref이면 검증한다. 표본8개 미만 층화는 유형10개 이상/전체 통계로 후퇴하며 전역Beta(1,1), 경험적 사전강도10을 사용한다. 안전한 산술 도구는 위험0, 유효답 해석 불능은 실패위험1이다. 확률 보장이나 최적 비용 환산식은 아니다.

새 보정100문제(유형별20), 새 평가150문제(유형별30)를 만들었다. 과거1022개 질문키와 보정/평가 사이에 중복0이다. 산술/코드는 독립 참조 검산, 지식·논리·지문은 수작업/생성 템플릿 정답이다. 동일150문제로 모델별3회, 온도0·seed42·출력64토큰 상한·동일 생성/검증 프롬프트를 적용했다. 모델마다 따로 보정하고 두 프로필을 모두 평가 전에 고정했다. 기존 Selective의 규칙은 유지하고 같은 새 보정으로 통계만 재산출했다. 이전150문제 결과와 정확도를 직접 혼합하지 않는다.

## 비용 추정과 위험 추정의 실패

두 모델 모두 학습한 비용 기울기가0이었다. 실제로는 주어진 문자 수에 따라 예측이 달라지지 않고1.5B92.225ms,0.5B41.303ms라는 보정 평균시간을 사용했다. 입력 길이만으로 검증 생성 길이·캐시·스케줄링을 설명하지 못했다. 이는 구현은 비용 추정식을 포함하지만 현재 데이터에서는 정교한 요청별 비용 적응이 작동하지 않았다는 한계다.

1.5B 주 RCAV는 검증0회여서 자체 실행에 대한 비용 예측오차를 측정할 수 없다. 동일 질문·동일 실제1차 답을 낸 Baseline의 별도 실행449건과 맞춘 **짝 참조**에서는 MAE13.835ms, MAPE14.91%였다. 0.5B 주 RCAV의 실제 실행된 검증50건은 MAE6.910ms, MAPE28.32%; 별도 Baseline 짝 참조449건은 MAE10.782ms, MAPE29.36%였다. 짝 참조는 실행 시점·캐시 상태가 달라 정확한 생략 호출의 반사실 비용이 아니다. 실제 실행 검증만의 오차는 선택 편향이 있다. 미실행 비용을 실측처럼 채워 넣지 않았다.

예:0.5B의 `v=[63,65,68]; print(v[1:][0])` 질문은 예상 검증41.303ms, 짝 참조 실제11.420ms로 과대추정했다. 1.5B의 `1278*47` 검증은 예상92.225ms, 짝 참조147.694ms로 과소추정했다. 후자는 안전도구라 검증을 생략한 사례지만 비용 모델이 실제 생성 길이를 놓쳤음을 보여준다.

주 RCAV의 비도구 위험 Brier 점수는1.5B0.1833,0.5B0.1874였다. 점수가 존재한다고 확률이 잘 보정됐다는 보장은 아니다. 반복 문항을 독립 표본으로 간주하지 않았고, 개별 오답 하나만으로 확률 예측이 잘못됐다고 단정하지 않는다. risk_diagnostics.csv는 예측확률과 실제 결과를 분리한다.

놓친 유용한 검증 예:1.5B의 `sum(range(62,69,2))`는 실제 정답260(D),1차 답248(C),Selective검증은D였다. RCAV 예상위험0.437, 예상 순오류감소0.0440이 비용 문턱0.0547보다 작아 검증하지 않았다. 0.5B의 원소기호Ca는 정답Calcium(B),1차Chlorine(A),Selective검증B였지만 RCAV 예상 순감소0.00238이 문턱0.06131보다 작아 놓쳤다. 비용 회귀만의 문제가 아니라 오류 수정/악화 확률의 작은 표본 수축·유형 일반화도 영향을 준다.

같은seed에서도0.5B의 슬라이스 질문 한 개가 두 반복에서는 설명문,세 번째에는 단일B로 바뀌었다. 둘 다 내용은 틀렸지만 해석 상태가 바뀌어 주 RCAV 검증수가17→16으로 변했다. 출력 형식과 위험 추정이 연결된 이 알고리즘은 이런 실행 변동에 민감하다. 원본 호출과 decision을 모두 보존했다.

## Pareto 해석과 퇴화 사례

관측 평균의 정확도 최대·답변율 비감소·모델시간/벽시계/CPU 최소 관계에서는1.5B의 λ=0.15가 frontier였다. 다만1.5B 주 RCAV와 λ=0.15는 모두150개 검증을 전부 생략해 행동이 동일했다. 시간 차이는 주로prefill/cache/순서 상태 차이에 해당할 수 있으므로 높은λ의 알고리즘 우위로 주장하지 않는다. 1.5B 개선은 해로운 재검증을 전반적으로 끈 결과이며, 유용한 검증을 골라 남기는 비퇴화 적응 능력은 입증하지 못했다.

0.5B에서는 λ=0,주 RCAV,λ=0.15가 서로 정확도·비용 trade-off로 frontier에 남았지만 주 RCAV와높은λ는 Selective 대비 품질 유지에 실패했다. frontier에 있다는 것과 연구 목표 달성은 다르다. 후보5점의 관측 관계일 뿐 전역Pareto 최적이나 유의성 검정이 아니다. pareto.csv에 탈락한 조건도 전부 공개했다.

**금전 비용·전력·GPU FLOPs는 미측정이다.** 실제 토큰·시간·CPU·RSS와 추정 위험·효과·검증시간을 별도 필드로 저장했다. 서버 warm-cache, 모델별 연속 실행, 합성 템플릿, 영어 객관식/코드출력예측, 확률/효과의 작은 표본, 내용 파서의 자유서술 한계가 남는다. 신규 질문 줄기라고 개념·템플릿 의미까지 독립적이라는 보장은 없다. 새로운 기술이라고 주장하지 않는다.

## 다음 연구 제안

단순 무검증 대조군을 사전 포함해 퇴화 정책을 구분하고, 별도 검증 데이터에서 품질 손실을 제한하는 가중치 선택/불확실성 기준을 검토할 가치가 있다. 비용 모델은 출력 길이·실행 상태·캐시·부하의 관측 가능 특성이 실제 예측력을 갖는지 먼저 검증해야 한다. 여기서는 평가를 보고 임계값을 재조정하거나 후속 알고리즘을 추가하지 않았다.
