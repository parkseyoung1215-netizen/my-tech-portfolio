## 성공 판단

각 세트에서 각 기준선 대비 **전체 정확도와 답변 비율이 모두 엄격히 증가해야 성공**이라는 기준을
실행 전에 고정했습니다. 2개 세트 × 3개 기준선의 6개 비교 모두 이 조건을 충족했습니다.
주 평가 300개 모두에 직접 답했으므로 거절을 늘려 빨라진 결과가 아닙니다.
기존 방식이 답했던 문제를 잃은 경우와 정답이 오답으로 바뀐 경우도 모두 0건입니다.

주 평가 전체에서 Tool-Assisted는 직접 계산 300회, 모델 호출 0회였습니다.
네 방식 전체는 1,200건의 요청 처리를 기록했고 기준선들은 실제 Ollama 모델을 총 852회 호출했습니다.
별도 안전 점검의 모델 호출 1회와 워밍업 4회는 주 평가 합계에서 제외했습니다.
네 방식 전체 평가 루프는 약 196.545초이며 진행 출력·채점 오버헤드를 포함합니다.

## 안전 적용과 fallback

파서는 입력 전체가 ASCII 정수·괄호·`+`, `-`, `*`·단항 부호로 이루어진 수식인지 확인합니다.
Python 소스 실행 없이 허용 AST 노드를 직접 계산합니다.
256자·64노드·깊이16·리터럴12자리·중간값128비트 제한이 적용됩니다.
설명 문장의 숫자만 임의 추출하거나 소수·나눗셈·함수 호출·거듭제곱을 추측해 계산하지 않습니다.

주 평가의 도구 오답·오적용·도구 fallback은 모두 0건입니다.
지원 수식만 있는 평가라 별도로 14개 사례를 실제 점검했습니다.

- 명확한 두 수식은 계산 도구가 직접 답했습니다.
- 미지원·안전 제한 12건은 기존 Adaptive 모델 라우터로 전달했습니다.
- 그중 `0002 + 0003`은 Python 정수 구문에서 선행 0을 허용하지 않아 도구가 거부했습니다.
  기존 라우터는 실제 0.5B를 한 번 호출했고 `FINAL_ANSWER: 0005`를 반환했습니다. 추출 정수는 5입니다.
- 나머지 11건은 기존 라우터도 적합한 모델을 찾지 못해 모델 호출 없이 거절했습니다.
- 중간 결과 제한 사례는 계산을 시작한 뒤 제한으로 중단했고 계산값을 반환하지 않았습니다.
- 14개 사례의 도구 오적용은 모두 0건입니다.

오적용은 빈 경우에도 별도 CSV에 헤더를 저장했고, fallback 12건은 별도 CSV에 남겼습니다.
이 점검 결과와 호출 수는 주 평가의 정확도·지연에 합산하지 않았습니다.

## 테스트와 무결성

전체 자동 테스트 **95개가 통과**했습니다. 테스트용 모의 모델 응답은 임시 디렉터리에만 사용했고
실제 성능 집계에는 포함하지 않았습니다.

- 기존 소스·실험 데이터의 해시를 실행 전후 대조해 보존을 확인했습니다.
- 문제 명세·프로필·소스 해시를 실행 전에 고정했습니다.
- 네 방식의 200개·100개 문제 집합이 각각 정확히 같은지 1,200행을 검사했습니다.
- 별도 AST 채점기로 모든 기준 정답을 검증했습니다.
- 독립 추출 파서 불일치는 0건입니다.
- 직접 도구 결과 300건 모두 정답이고 모델 시도 기록이 없음을 확인했습니다.
- 기대 정답은 계산기·라우터에 전달하지 않고 사후 채점에만 사용했습니다.

## 해석의 범위

명확한 정수 산술식에서는 모델에게 계산을 재생성시키는 비용을 제거하는 방식이 효과적이었습니다.
이것이 모델 자체의 추론 능력이 좋아졌거나 일반 AI 작업의 품질이 향상됐다는 의미는 아닙니다.
비산술 fallback의 응답 가능성은 기존 라우터의 한계를 그대로 가집니다.

금전 비용·전력·CPU·메모리·FLOPs는 **미측정**입니다. 금전 절감률을 추정하지 않았습니다.
모델 호출이 없어도 Ollama의 상주 모델 메모리·유휴 비용이 사라지는 것은 아닙니다.
아주 짧은 도구 지연은 프로세스 시작이나 모듈 로딩 시간이 아닌 준비된 런타임의 요청 처리 시간입니다.
단일 실행이므로 반복·부하·새로운 문제 유형 검증이 필요합니다.
