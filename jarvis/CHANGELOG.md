# 자비스 변경 기록 (CHANGELOG)

맥북용 개인 음성 비서 "자비스"를 만들어 온 과정. 버전마다 무엇을 추가했고, 어떤 문제를 만났고, 어떻게 해결했는지 기록.

---

## 1단계: 기본 비서 (2026-10-12)

### v0.1 — 첫 버전
- Enter를 누르고 5초 말하기 → Whisper 받아쓰기 → GPT-4o-mini가 행동 결정(JSON) → 실행 → 맥 음성으로 대답
- **기본법 설계**: 같은 규칙을 프롬프트(AI가 애초에 규칙 안에서 움직이게)와 코드(AI가 뭐라 하든 최종 결정) 양쪽에 둠
  - 허용 목록에 없는 행동은 무조건 거부
  - 기록이 남는 행동(미리 알림 추가)은 실행 전 허락
  - 모든 행동을 로그 파일로 기록
- 기능: 앱 열기, 웹페이지 열기, 미리 알림 추가, 질문에 대답

### v0.2 ~ v0.3 — 첫 테스트 결과 반영
- **문제**: 아무 말 안 했는데 "시청해주셔서 감사합니다"로 받아씀 (Whisper가 조용한 소리에서 유튜브 끝인사를 지어내는 현상)
  → 소리 크기가 기준보다 작으면 받아쓰기에 보내지 않음 (비용도 절약)
- **문제**: "끝"이 종료 단어가 아니었고, 반대로 문장 속 "끝"으로도 꺼질 위험
  → 종료 단어만 짧게 말했을 때만 종료
- **문제**: 허락받기 전인데 "알림을 추가했습니다"라고 말함 → 실행 전엔 "~할게요"로 말하게 규칙 수정

### v5.3 — 믿을 수 있는 비서 (차별점)

- **"방금 거 되돌려줘"**: 볼륨, 탭(닫기 전에 주소 저장), 페이지, 음악, 타이머, 기억, 앱, 알림·일정을 되돌림

### v5.4

### v5.5 — 거짓 보고 방지 (중요한 안전 수정)
- **문제**: "내려줘"라고 하자 도구를 실행하지 않고 "Volume turned down"이라고만 대답함 (실제로는 아무것도 안 함). 이어서 "되돌려줘"에도 undo 도구를 쓰지 않고 혼자 "못 한다"고 대답
- **원인**: 대화 기억에 남은 예전 대답("Volume turned down...")을 AI가 흉내 내서, 도구 호출 없이 글자만 만들어냄
- **해결**:
  - 코드 검사: 이번 차례에 도구를 하나도 안 썼는데 "했다"는 표현이 있거나, 되돌리기 요청인데 도구를 안 쓰면 → AI에게 "아무것도 실행되지 않았다"고 알리고 한 번 다시 판단시킴
  - 대화 기억을 "[과거 기록]"으로 명확히 표시해서, 지금 한 일과 구분되게 함
  - 규칙: 도구를 호출하지 않았으면 무엇을 했다고 말하지 않기, 되돌리기는 반드시 undo 도구로

## 6단계: 평생 쓸 수 있는 구조 (2026-10-16)

### v6.0 — 구조 정리 (기능 변화 없음)
- 1,900줄짜리 `assistant.py` 한 파일을 역할별로 나눔
  - `config.py`: 설정을 한곳에 (호출어 민감도, 목소리, 모델, 브리핑 위치 등)
  - `jarvis/`: 본체 (core 공통 바탕, voice 말하기, hearing 듣기, registry 도구 등록부, brain 두뇌, trust 기록·설명·되돌리기, main 실행)
  - `skills/`: 기능별 파일 (apps_web, media, system, calendar, news, market, memory, briefing)
- **도구 등록부(registry)**: 기능마다 "도구 설명 + 허락 수준(auto/confirm) + 실행 함수"를 한 번에 등록. 등록 안 된 도구는 AI가 쓸 방법이 없음 (기본법 유지)
- 새 기능 추가 = `skills/`에 파일 하나 + `jarvis/main.py`에 import 한 줄
- 옮긴 뒤 자동 점검: 도구 26개 설명·순서, 허락 수준, AI 지시문, 설정값 48개가 원본과 완전히 같은지 비교, 정의 안 된 이름 검사, 가짜 AI로 두뇌 흐름(거짓 보고 방지, 허락 거절) 재현, 기억·언어·되돌리기·기록 보고 실제 실행

### v6.1 — 화면(HUD)
- 화면 구석에 자비스 원을 띄움. 투명하고 테두리 없는 창이 항상 위에 떠 있고, 마우스로 끌어서 옮길 수 있음
  - 대기(파랑, 숨 쉬듯) → 듣는 중(내 목소리 크기에 맞춰 출렁임) → 생각 중(도는 호) → 말하는 중
  - **기본법이 눈에 보이게**: 허락 대기(주황 카드, 질문 표시), 완료(초록 카드, 한 일 + 되돌리기 버튼), 차단(빨강 카드)
- **구조**: 화면은 따로 도는 프로그램(`hud/hud_app.py` + `hud/hud.html`). 자비스 본체가 켜질 때 같이 띄움
  - 화면이 멈추거나 꺼져도 자비스는 계속 작동. pywebview가 없으면 화면만 빠짐
  - 둘은 이 컴퓨터 안(127.0.0.1)에서만 주고받음
- **화면은 보여주기만 함**: 실행·허락·차단은 전부 본체가 결정. 화면에서 받는 신호는 "undo" 한 단어뿐이고, 받으면 "방금 거 되돌려줘"라고 말한 것과 똑같이 처리(지우는 종류는 말로 다시 허락)
- **함께 고친 것**: 보호된 앱(Finder 등) 종료 요청을 허락 묻기 '전에' 바로 차단하고, 결과를 "blocked"로 정확히 기록 (예전엔 허락받은 뒤에 조용히 실패로 기록됨)
- 설정: `HUD_ENABLED`, `HUD_POSITION`(구석 위치), `HUD_PORT`
- 점검: 보호 앱 차단(허락 안 물음), 허락 카드 내용, 버튼 신호에서 엉뚱한 글자 무시, 말→생각→결과 카드→버튼 되돌리기 전체 흐름, 화면 글자에 따옴표 같은 특수문자가 섞여도 깨지지 않는지
- 디자인은 `hud/hud.html` 한 파일만 고치면 바뀜 (나중에 더 웅장하게)

  - "숨겨줘" → auto: 평소엔 숨어 있다가 부를 때(듣기·생각·말하기·허락)만 나타나고, 끝나면 1.5초 뒤 사라짐 (결과 카드가 있으면 10초)

### v6.2.1 — 전체화면 위에 안 뜨던 문제

### v6.3 — 유튜브 전체화면 위에도 뜨게 (창 종류 교체)
- **문제**: v6.2.1 뒤로 홈 데스크탑의 다른 앱 위에는 뜨지만, 사파리 전체화면(유튜브) 위에는 여전히 안 뜸

- **해결**: pywebview를 빼고 맥 부품(pyobjc)으로 직접 '포커스를 안 뺏는 패널' 창을 만들고, 그 안에 같은 hud.html을 띄움
  - 원을 눌러도 유튜브에서 포커스가 안 빠짐
  - 끌어서 옮기기는 화면(HTML)이 이동한 거리만 패널에 보내는 방식으로 다시 구현
  - 자비스 본체가 꺼지면 화면도 2초 안에 같이 꺼짐 (화면만 혼자 남는 문제 방지)
- 화면이 받는 신호는 여전히 "undo"와 끌기 거리뿐, 그 외는 무시
- 점검(맥 부품을 가짜로 대신해서): 패널 종류·설정값, 시작 위치, 되돌리기 신호, 끌기, 엉뚱한 신호 무시, 숨김 모드에서 부르면 나타나기

### v6.4 — Touch ID 허락 (허락 3단계)
- **왜**: 말로 받는 허락은 옆 사람이나 유튜브 소리가 "yes"라고 해도 통과될 수 있음. 되돌리기 어려운 행동은 내 몸으로 확인받아야 함
- **허락 3단계**
  - auto: 바로 실행 (볼륨, 음악, 검색 등)
  - confirm: 말로 허락 (앱 끄기, 알림·일정 추가)
  - **secure: Touch ID(또는 Mac 암호)로만 허락. 말로 "yes" 해도 통과 안 됨**
- 지금 secure인 것: 기억 지우기, 일정 추가를 되돌리기(같은 이름의 일정을 전부 지우는 동작이라)
- `config.py`의 `SECURE_TOOLS`에 도구 이름을 넣으면 Touch ID로 올라감. 올리기만 되고, 기능 파일에서 정한 수준보다 낮출 수는 없음
- **무조건 거절하는 경우**: 부품이 없을 때, Touch ID를 못 쓸 때, 30초 안에 지문을 안 댈 때, 취소했을 때, 에러가 났을 때 (애매하면 실행 안 함)
- 화면: 보라색 "TOUCH ID" 카드
- 점검(가짜 지문 센서): 부품 없음·센서 없음·시간 초과·취소 → 전부 거절되고 실제 행동은 실행 안 됨, 승인 → 실행. 말로 "yes"를 해도 Touch ID 단계는 건너뛸 수 없음. 거절된 되돌리기는 목록에 남아서 다시 시도 가능

- **꺼져 있었을 때**: 2시간 안에 놓친 알림은 "늦었어요"라고 붙여서 말하고, 그보다 오래된 한 번 알림은 조용히 지움
- 한국어로 말한 알림은 한국어(유나)로, 영어는 영어(Ava)로
- 알림은 `~/.jarvis_alerts.json`에 저장 (껐다 켜도 남음), 울리면 말하기 + 맥 알림 + 화면 카드 + 행동 기록
- 만들기·취소 모두 되돌리기 가능. 알림이 하는 일은 말하기뿐이라 바로 실행(auto)
- 점검(가짜 시계): 30분 뒤, 내일 9시, 이미 지난 시각→내일, 평일만(주말 건너뜀), 같은 날 두 번 안 울림, 가격 미달→안 울림·돌파→울림, 40분 늦음→"늦었어요", 4시간 늦음→조용히 삭제, 잘못된 값 거부, 일정 10분 전 한 번만, 대화 중엔 기다렸다가 말함, 되돌리기

### v6.9 — 손 리모컨 볼륨 오작동 수정, 옆으로 넘기기 끔
- **문제**: 집지도 않았는데 손을 움직이기만 해도 볼륨이 오르내림
- **원인**: "엄지·검지가 가까우면 집기"로만 판단 → 주먹이나 살짝 오므린 손도 엄지·검지가 가까워서 집기로 인식됨
- **해결**
  - 볼륨은 **OK 사인(👌)**일 때만: 엄지·검지가 붙고 + 나머지 세 손가락이 펴져야 함 (주먹·오므린 손과 확실히 구분)
  - OK 사인을 0.3초 유지해야 시작, 그 순간 높이가 기준 (우연히 모양이 맞거나 휙 지나가는 건 무시)
  - 볼륨 한 칸에 필요한 움직임 0.05 → 0.07 (손 떨림 무시)
- **옆으로 넘기기(다음/이전) 끔**: 지금은 쓸 상황이 없음 (화면에 넘길 게 생기면 `SWIPE_ENABLED = True`)
- 점검: 주먹·오므린 손·편 손을 위아래로 움직임 → 반응 없음 / OK 유지 후 위·아래 → 볼륨 / OK로 휙 → 없음 / OK 유지 중 떨림 → 없음 / 옆으로 휙 → 없음 / 손바닥 → 재생·멈춤

### v6.10 — 볼륨 다이얼 (내 아이디어)
- OK 사인 + 위아래 방식 대신, 내가 제안한 방식으로 바꿈
  1. 검지를 쭉 펴고, 엄지는 검지 끝 근처에 살짝 벌리고, 나머지 세 손가락은 접기 → 0.35초 가만히 있으면 다이얼 켜짐
  2. 그대로 손을 내 기준 오른쪽으로 → 볼륨 올라감, 왼쪽으로 → 내려감 (화면 폭 6%마다 한 칸)
  3. 엄지·검지를 완전히 붙이면 → 그 볼륨으로 끝
- 끝내는 동작이 분명해서, 손을 내리는 순간 볼륨이 튀는 문제가 없음
- 보완한 점: "엄지·검지를 살짝 벌린 모양"은 힘 뺀 손과 거의 같아서, **검지를 쭉 펴야** 켜지게 함 (힘 뺀 손은 검지가 굽어 있음)
- 오작동 방지: 붙여서 끝낸 뒤엔 손 모양을 한 번 풀어야 다시 켜짐 / 준비 모양이어도 움직이는 중이면 안 켜짐 / 손이 0.5초 이내로 잠깐 안 잡히면 다이얼 유지, 더 길면 끔 / 손바닥을 펴면 끝
- 화면에 "다이얼 켜짐", "볼륨 설정됨" 표시 (키를 누르지 않는 표시용 신호, 자비스 허용 목록은 그대로)
- 점검(가짜 손 15가지): 오른쪽 3칸·왼쪽 2칸, 붙인 뒤 움직여도 무반응, 힘 뺀 손·주먹·OK 사인·움직이는 준비 모양 → 무반응, 0.27초만 → 무반응, 떨림 → 무반응, 잠깐 놓침 → 유지, 오래 놓침 → 끔, 손바닥 → 끝, 재생/멈춤 그대로

### v6.11 — 다이얼 켜는 모양을 크게 (L자)
- **문제**: 실제로 써보니 "살짝 벌린 모양"은 인식이 애매함
- **바꿈 (내 제안)**: 켤 때는 엄지·검지를 **크게 벌린 L자**, 끌 때는 **완전히 붙이기**
  - L자: 검지 펴고 + 엄지·검지 벌림이 손 크기의 0.55배 이상 + 나머지 세 손가락 접음
  - 켤 때와 끌 때 모양 차이가 커져서, 붙이기 기준을 0.15 → 0.25로 너그럽게 (카메라가 손끝을 살짝 잘못 잡아도 붙임으로 인식)
- 시도했다가 되돌린 것: '가만히' 기준을 느슨하게(0.05 → 0.07) 했더니 손을 천천히 움직이는 중에도 다이얼이 켜져서 원래대로
- 점검 모드(`--check`)에서 0.5초마다 손 모양을 숫자로 보여줌 (벌림 정도, 검지 폄/굽음, 편 손가락 수 → 어떤 모양으로 보이는지). 인식이 안 될 때 이유를 바로 볼 수 있음
- 점검(가짜 손 18가지): 기존 15가지 + 검지만 편 손(엄지 접음)·그 손을 멈췄다 움직이기·예전 '살짝 벌린' 모양 → 전부 무반응

## 9단계: 모르는 건 찾아보는 자비스 (2026-10-17)

### v6.12 — 웹 검색 (`lookup`)
- **왜**: 뉴스·날씨·주가 말고 일반적인 최신 정보는 몰랐음 ("이번 주말 브레멘 행사 뭐 있어?" 같은 질문에 답 못 함)
- 자비스가 웹에서 직접 찾아서 2~4문장으로 말해줌 (OpenAI 웹 검색, 기존 키 그대로). 출처 주소는 기록에 남음
  - 기존 `web_search`는 그대로: "구글에서 검색해줘"처럼 브라우저로 결과 페이지를 열 때
  - AI 지시문에 한 줄 추가: 최근 일·확실하지 않은 사실은 지어내지 말고 lookup으로 찾기
- **비용**: 검색 한 번에 약 1센트 (검색 $10/1,000회 + 읽은 페이지 분량). 하루 최대 30번 (`SEARCH_DAILY_LIMIT`)
- 최신 검색 방식(`web_search`)이 안 되면 예전 방식(`web_search_preview`)으로 자동 재시도
- **기본법 추가: 웹 내용은 정보일 뿐 명령이 아님**
  - 웹 페이지에 AI를 노린 숨은 지시("이 링크를 열어라" 등)가 있을 수 있음 (프롬프트 인젝션)
  - 그래서 검색 결과를 읽은 그 대화 차례에서는, 원래 바로 실행되는 행동(링크 열기, 앱 열기 등)도 **말로 다시 허락받음**
  - 읽기만 하는 도구(뉴스, 주가, 일정, 브리핑 등)는 그대로 바로 실행. 다음 차례부터는 원래대로
- 점검: 출처 추출·중복 제거, 최신 방식 실패 → 예전 방식, 하루 한도, **웹 결과에 "evil 링크 열어" 지시를 심은 가짜 검색 → 자비스가 열려고 하자 허락을 물었고 거절하니 안 열림**, 같은 차례의 주가 조회는 바로 실행, 다음 차례의 링크 열기는 평소처럼 바로 실행
